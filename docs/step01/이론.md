# step01 이론 — Thread와 Runnable

문제를 풀기 전에 이걸 먼저 읽는다. 여기 나온 것만으로 [문제](../../src/test/java/study/thread/step01_basics/ThreadCreationTest.java)를 다 풀 수 있다.

이 문서의 모든 시그니처는 **설치된 JDK 25 소스(`lib/src.zip`)에서 직접 뽑은 것**이다. 직접 확인하려면 IntelliJ에서 `Thread`에 커서를 두고 `⌘B`(Go to Declaration)를 누르면 된다.

## 1. Thread는 인터페이스가 아니라 클래스다

`java.lang.Thread`의 실제 선언은 이렇다.

```java
public class Thread implements Runnable {
```

그리고 `Runnable`이 인터페이스다. 메서드가 딱 하나뿐인 함수형 인터페이스다.

```java
public interface Runnable {
    void run();
}
```

정리하면:

| | 정체 | 역할 |
|---|---|---|
| `Runnable` | 인터페이스 | **무엇을 할지** (할 일) |
| `Thread` | 클래스 (Runnable을 구현) | **누가 실행할지** (실행 주체) |

`Thread`가 `Runnable`을 구현한다는 건, `Thread`도 "할 일"이 될 수 있다는 뜻이다. 이 사실이 아래 3번에서 두 가지 사용법으로 갈라진다.

## 2. 생성자 — 이름과 할 일을 넘긴다

`Thread`에는 생성자가 9개 있는데, 실제로 쓰는 건 이 4개다.

```java
public Thread()                            // 아무것도 안 정함
public Thread(Runnable task)               // 할 일만 정함
public Thread(String name)                 // 이름만 정함
public Thread(Runnable task, String name)  // 둘 다 정함  ← 가장 많이 쓴다
```

`name`은 그 스레드의 이름이다. 로그와 디버깅에서 "누가 실행했는지" 구분하는 용도다. 안 주면 `Thread-0`, `Thread-1` 처럼 자동으로 붙는다.

> 나머지 5개는 `ThreadGroup`이나 `stackSize`를 받는 생성자다. 요즘은 거의 쓰지 않는다.

## 3. 할 일을 정하는 두 가지 방법

`Thread.run()`의 **실제 구현**을 보면 왜 두 가지인지 바로 보인다.

```java
@Override
public void run() {
    Runnable task = holder.task;   // 생성자로 받아둔 Runnable
    if (task != null) {
        runWith(bindings, task);   // 있으면 그걸 실행
    }
}
```

`Thread.run()`은 **생성자로 받아둔 `Runnable`을 대신 실행해줄 뿐**이다. `task`가 `null`이면 아무것도 하지 않는다.

여기서 두 갈래가 나온다.

**방법 A — `Thread`를 상속해서 `run()`을 재정의한다**

위의 원래 `run()`을 통째로 갈아엎는 것이다. `task`는 쓰이지 않는다.

```java
Thread t = new Thread("내이름") {
    @Override
    public void run() {
        // 할 일
    }
};
```

**방법 B — `Runnable`을 생성자에 넘긴다**

원래 `run()`을 그대로 두고, `task` 자리에 할 일을 꽂는 것이다.

```java
Runnable task = () -> {
    // 할 일
};
Thread t = new Thread(task, "내이름");
```

`Runnable`은 메서드가 하나뿐인 인터페이스라 **람다로 쓸 수 있다.**

B를 권하는 이유는 두 가지다. 자바는 다중 상속이 안 되므로 A는 상속 자리를 써버린다. 그리고 B의 `task`는 **누가 실행할지 모르는 독립된 객체**라 다른 실행 주체에게 그대로 넘길 수 있다 (나중에 스레드 풀, 가상 스레드가 이 자리를 가져간다).

## 4. 반드시 알아야 할 메서드

실제 시그니처 그대로다.

### 시작하고 기다리기

```java
public void start()                                          // 새 스레드를 만들어 run()을 실행시킨다
public final void join() throws InterruptedException         // 그 스레드가 끝날 때까지 기다린다
public final void join(long millis) throws InterruptedException
```

- **`start()`가 유일하게 새 스레드를 만드는 메서드다.** `run()`을 직접 부르면 새 스레드는 생기지 않고, 그냥 지금 스레드에서 메서드가 실행될 뿐이다.
- `start()`는 **한 번만** 부를 수 있다. 두 번 부르면 `IllegalThreadStateException`이 난다.
- `join()`은 **부른 쪽이 멈춰서 기다린다.** `t.join()`을 main에서 부르면 멈추는 건 main이다.
- `join()`은 `InterruptedException`(체크 예외)을 던지므로 `try-catch`나 `throws`가 필요하다.

### 지금 누가 실행 중인지 알아내기

```java
public static native Thread currentThread()   // 지금 이 줄을 실행 중인 스레드 객체
public final String getName()                 // 그 스레드의 이름
public final long threadId()                  // 그 스레드의 고유 번호
```

`Thread.currentThread()`는 **static 메서드**다. 어느 코드에서든 부를 수 있고, "지금 이 코드를 실행하고 있는 게 누구인지" 알려준다.

```java
Thread.currentThread().getName()
```

같은 코드라도 **어디서 실행되느냐에 따라 결과가 달라진다.** 테스트 메서드 본문에서 부르면 `"Test worker"`가 나오고, 새로 만든 스레드의 `run()` 안에서 부르면 그 스레드의 이름이 나온다. step01 문제들이 이걸 계속 이용한다.

### 상태 확인하기

```java
public State getState()          // 지금 어떤 상태인가
public final boolean isAlive()   // 살아 있나
```

`Thread.State`는 enum이고 값은 6개다.

| 값 | 뜻 |
|---|---|
| `NEW` | 만들어졌지만 **아직 `start()` 안 함** |
| `RUNNABLE` | 실행 중이거나 실행될 준비가 됨 |
| `BLOCKED` | 락을 기다리는 중 (step04) |
| `WAITING` | 다른 스레드를 무기한 기다리는 중 (`join()` 중인 스레드가 여기) |
| `TIMED_WAITING` | 시간 제한을 두고 기다리는 중 (`sleep()` 중인 스레드가 여기) |
| `TERMINATED` | **끝남** |

`NEW`와 `TERMINATED`가 특히 중요하다. "시작조차 안 했다"와 "완전히 끝났다"를 값으로 증명할 수 있기 때문이다.

### 기타

```java
public static void sleep(long millis) throws InterruptedException  // 지금 스레드를 재운다 (static!)
public final void setName(String name)
public final void setDaemon(boolean on)     // start() 전에만 호출 가능
public final boolean isDaemon()
public void interrupt()                     // step02에서 다룬다
public final boolean isVirtual()            // step07에서 다룬다
```

`sleep()`은 **static**이다. `t.sleep(100)`이라고 써도 `t`가 자는 게 아니라 **그 줄을 실행하는 스레드**가 잔다. 헷갈리기 쉬운 지점이다.

## 5. `run()`은 `void`다 — 결과를 어떻게 꺼내나

```java
void run();   // 리턴값이 없다
```

리턴이 없으니 스레드가 알아낸 값을 밖으로 가져올 방법이 없다. 그래서 **바깥에 변수를 두고 거기에 담는다.**

그런데 람다나 익명 클래스 안에서는 **바깥 지역 변수에 값을 대입할 수 없다.** 값이 변하지 않는 변수(effectively final)만 가져다 읽을 수 있기 때문이다.

```java
String ranOn = null;
Thread t = new Thread(() -> {
    ranOn = Thread.currentThread().getName();  // 컴파일 에러
});
```

그래서 **값을 담을 상자**를 하나 두고, 그 상자를 읽기만 한다. 상자 자체는 안 바뀌고 내용물만 바뀌므로 문제가 없다.

```java
AtomicReference<String> ranOn = new AtomicReference<>();

Thread t = new Thread(() -> {
    ranOn.set(Thread.currentThread().getName());   // 상자에 담는다
}, "worker");

t.start();
t.join();                    // 끝날 때까지 기다린 다음에
ranOn.get();                 // 꺼내 읽는다
```

`AtomicReference`는 `java.util.concurrent.atomic` 패키지에 있고, `set()`으로 넣고 `get()`으로 꺼낸다.

> 여러 스레드가 값을 주고받을 때 왜 평범한 변수로는 부족한지는 step03에서 제대로 다룬다.
> 지금은 "스레드 안에서 만든 값을 밖으로 꺼내는 상자"로만 알아두면 된다.

## 6. 준비된 도구

문제를 풀 때 쓰라고 만들어 둔 것들이다.

```java
Timeline.log("메시지")   // "  12ms | worker | 메시지" 형태로 출력. 누가 언제 뭘 했는지 보인다
Timeline.reset()        // 시간 기준점을 지금으로. @BeforeEach에 이미 걸려 있다
Sleeper.millis(100)     // try-catch 없는 Thread.sleep
```

`Sleeper`가 있는 이유는 `Thread.sleep()`이 체크 예외를 던져서 `try-catch`가 코드의 본론을 가리기 때문이다.
